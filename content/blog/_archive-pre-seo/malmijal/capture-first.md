말미잘의 분석 파이프라인은 한 가지 원칙으로 시작했습니다.

> 사용자의 녹음은, 어떤 경우에도 잃지 않는다.

## 흔한 함정

음성 처리 앱에서 자주 보이는 흐름은 이렇습니다. 녹음 → 분석 호출 → 결과 받으면 저장. 이 순서의 문제는, 분석 단계에서 무엇이라도 잘못되면 사용자의 녹음 자체가 함께 사라진다는 것입니다. 모델이 죽거나, 큐가 막히거나, 네트워크가 끊기면, 사용자는 다시 녹음해야 합니다.

매일의 훈련을 다루는 앱에서 이 경험은 치명적입니다.

## Capture-First

말미잘은 순서를 뒤집습니다. 녹음이 끝나는 즉시 원본 WAV 가 Supabase Storage 에 영속화됩니다. 분석은 그 다음, 별도의 비동기 작업으로 트리거됩니다.

```
[녹음 완료]
  → [원본 WAV 저장]    ← 실패 불가능 영역
  → [분석 job 큐]       ← 실패 가능 / 재시도 가능
       → 결과 도착 시 Realtime push
```

분석이 실패하면 다시 시도할 수 있습니다. 모델이 바뀌면 과거 녹음을 다시 돌릴 수 있습니다. 무엇보다, 사용자는 절대 다시 녹음하지 않아도 됩니다.

## 결과는 비동기로

분석 결과는 Supabase Realtime 을 통해 푸시됩니다. 사용자가 결과 화면을 보고 있을 필요가 없고, 다른 화면에 있어도 결과가 도착하면 알림이 옵니다.

## 트레이드오프

이 구조의 비용은 명확합니다. 사용자가 한 번도 듣지 않을지도 모르는 녹음을 모두 저장합니다. 스토리지 비용이 듭니다.

그럼에도 이 비용을 지불하기로 한 것은, 매일 훈련하기로 한 사용자에게 "다시 녹음하세요"라고 말하지 않기 위해서입니다.
